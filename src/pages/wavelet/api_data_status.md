# Wavelet API Data Implementation Status

This document outlines exactly how much of the backend data from the `curl` response is dynamically consumed in our current React implementation, and what parts are currently using static/dummy fallbacks.

## 🟢 1. Fully Dynamic (Working perfectly from API)
These elements are completely driven by the live data from the backend:

- **Main Candlesticks (`WaveletChart.jsx`)**: 
  - Fed directly from `data.meta.candles`. All `open`, `high`, `low`, `close`, and `time` values are 100% dynamic.
- **Wavelet Signal Line (`WaveletSignalPane.jsx`)**: 
  - Maps precisely to `data.wavelet.signals`. Uses the `wave` property for the blue signal line.
- **Signal Momentum Histogram (`WaveletSignalPane.jsx`)**:
  - Maps directly to the `momentum` property in `data.wavelet.signals`. Colors (Green/Red) are dynamically calculated based on whether momentum is positive or negative.
- **BUY/SELL Markers (`WaveletSignalPane.jsx`)**:
  - Dynamically generated by checking `s.signal === "UP" / "BUY"` and `"DOWN" / "SELL"` from the API.

## 🟡 2. Partially Dynamic (Uses API data but has static fallbacks)
These elements read from the API, but have static "dummy" fallbacks in the code just in case the backend payload structure doesn't exactly match the expected JSON keys.

- **Chaos Fractal Top/Bottom Markers (`WaveletChart.jsx` & `ChaosFractalPane.jsx`)**:
  - We read the time and signal correctly from the `data.fractals` object array.
  - *Dummy aspect:* The oscillator "strength" line in the fractal pane uses a fallback math formula (`Math.sin(i * 0.5) * 1.5`) because the exact `strength` key wasn't fully visible during the initial payload inspection. If `f.strength` exists in the backend, it will use it dynamically!
- **Dashboard Stats (`RightPanel.jsx` & `BottomPanel.jsx`)**:
  - We actively attempt to pull from `data.dashboard` and `data.wavelet.latest` (e.g., `trendStrength`, `confidence`, `market.state`).
  - *Dummy aspect:* If those specific nested keys are missing or named differently, it defaults to the exact text from your reference image (e.g., "78%", "20 Jun 15:00").

## 🔴 3. Fully Static / Dummy Data
These elements are currently hardcoded for visual UX purposes and do not use the live backend calculations yet.

- **Wavelet Heatmap Matrix (`WaveletHeatmapPane.jsx`)**:
  - *Current State:* It draws a static, stylized HTML5 Canvas gradient (Blue -> Green -> Yellow -> Red) and static labels ("Bullish Wave Energy") to exactly match the screenshot's aesthetics.
  - *Why?* Translating a raw 2D array of energy values (`data.heatmap`) into a continuous visual spectrum on a Canvas requires a dedicated mathematical rendering loop. We mapped the UI layout perfectly, but the pixels themselves do not shift with live data.

## Next Steps for 100% Dynamic Integration
If you want to remove the remaining dummy fallbacks, we would need to:
1. Console log the exact properties inside `data.dashboard.summary` to replace the static dates.
2. Ensure `data.fractals` explicitly returns a `strength` property for the oscillator.
3. Write a complex Canvas decoding loop for `data.heatmap` to paint individual energy pixels based on the `color` and `importance` arrays from the API.
